# 单店角色与经理接管商家职责

本分支按单店经营，不考虑多商家隔离。业务角色统一为：

- `customer`：购物、本人订单、本人退货申请。
- `store_manager`：全平台商品、库存、仓库、销量与预测、经营订单查询及评价回复模板。
- `admin`：平台概览、运行监控、Agent 授权、审批队列、退货收货和退款审批；不购物，也不访问经理经营接口。

三个身份互不继承业务权限。只有顾客可以使用购物车、结算和个人订单；只有经理可以操作全店商品、库存、营销、分析和经营订单。管理员使用独立的平台与审批接口。
HTTP 接口、页面导航与路由、AI 工具均执行相同边界；角色鉴权始终启用，不受 `GUARDRAILS_ENABLED` 内容安全开关影响。

`products.seller_id` 暂时保留用于兼容历史数据，既不作为经理的数据范围，也不要求新商品填写。
经理可以查看、修改或上下架任何已有商品，新增商品后也能立即在全店商品和库存管理中操作。
所有库存改动仍通过 `change_inventory` 记流水，不直接覆盖数量。

## 页面与接口

管理员登录进入 `/admin`，顾客进入 `/chat`，经理进入 `/analysis`。经理侧边栏增加 **Store Overview** (`/management`)。
概览展示全店商品数、订单数、非取消订单商品小计与最近订单。
**Item Sales Amount** 含退货订单商品小计，未分摊整单折扣、未扣除退款，不代表净收入。
管理商品与上下架进入 `/inventory`，经营商品和分析入口保持 `/products`、`/analysis`。

旧 `/seller` 跳转到 `/management`；旧 `/seller/products` 跳转到 `/products`，不再提供独立商家入口。

只有经理可访问以下全店接口，顾客和管理员返回 403，未登录返回 401：

- `GET /api/manager/store/products`：全部商品，包含下架及无历史商家归属的商品；支持 `category`、`limit`、`offset`。
- `GET /api/manager/orders`：全店订单；支持 `status`、`limit`、`offset`，多商品订单不重复统计。
- `GET /api/manager/store/stats`：`product_count`、`order_count`、`item_sales_amount`、`avg_rating`、`sales_definition`。
- 商品/库存/仓库写接口继续使用 `/api/manager/products`、`/api/manager/inventory`、`/api/manager/warehouses`。

旧 `/api/seller/products`、`/api/seller/orders`、`/api/seller/stats` 是弃用的经理兼容地址，返回上述新结构，
不再按 `seller_id` 过滤，也不接受旧 `seller` 身份。新代码使用经理地址。

## AI 工具

新增并注册 `get_store_products`、`get_store_orders`、`get_store_stats`、`get_store_inventory`。
Product Discovery、Order Management、Inventory & Fulfillment 分别调用相关工具读取全店数据。
这些工具的经理权限不依赖可选 guardrails 开关，顾客不能通过聊天获取经营数据。

经理可调用评价回复模板和履约规划；缺货预订属于顾客购物工具，经理和管理员均不可调用。
`draft_seller_response` 为兼容旧工具调用保留名字，权限仅限经理，生成模板不会自动发布。
原有缺货预订仍是演示行为，不能理解为真实采购。
复用的 specialist 在每轮请求注入当前角色指令，不固化启动时的 customer 身份。

顾客取消、退货和退款请求仅限 customer，并继续按订单归属校验；经理不能利用全店读取权限操作顾客购物车或绕过管理员退款审批。
营销生图/文案仍从新增商品表单触发，未新增营销聊天工具。

## 三角色职责隔离修正（2026-10-31）

管理员不再继承经营权限；`/api/manager/*` 及旧 `/api/seller/*` 只允许经理。
管理员仍可在 `/api/admin/*` 执行退货收货及退款审批；收货时由业务事务产生的库存流水属于售后流程，不是经理库存管理入口。
购物 API 和 AI 工具只允许顾客；经理与管理员不能创建购物车、结算、取消个人订单或发起个人退货。
后台不删除旧账号、历史购物记录、商品、订单或库存，不修改迁移 001–007；此次无需新增数据库迁移。
